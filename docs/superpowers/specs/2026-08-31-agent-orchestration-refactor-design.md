# Agent 编排化魔改设计（RAG 项目 → Agent 项目）

> 2026-08-31 经三轮 grill 烤问定稿。目标：3 周内将面试官模块升级为符合 Agent 开发岗位 JD 的
> 多阶段确定性编排 Agent 系统，并完成可演示、可评测、可归因的完整闭环。
> 背景：项目原处于 CODE FREEZE + 技术复盘阶段，本设计是唯一例外的新功能开发，在独立分支进行。

---

## 1. 目标与定位

**一句话定位（简历/开场话术）**：
面向 Java 岗位的自适应 AI 面试官：确定性编排 + LLM 角色节点的多阶段 Agent 系统。

- 「确定性编排」放进第一句话，直接对准目标 JD 的技术路线表态（流程编排与规则校验由确定性代码实现）。
- RAG 降级为其中一个工具能力被提及，避免项目被归类为「RAG 项目」。

**JD 职责映射**（本项目对应物）：

| JD 职责 | 本项目对应物 |
|---|---|
| 多阶段状态机、阶段门禁 | 出题→追问→评估→难度调整→总结 的阶段流转 + 门禁（评估不通过降难度重问） |
| 角色定义、按阶段注入领域知识、结构化输出+重试 | 每阶段一个 Role（出题人/追问者/评估官），从 KG/RAG 注入知识，JSON Schema 校验 |
| 确定性工具层、MCP 客户端 | RetrievalFacade 封装为 MCP server + 规则校验工具 |
| 统一模型接入、分级调用 | 百炼 turbo（轻任务）/ plus（生成）+ 硅基流动（rerank），统一接口 + 降级链 + 成本统计 |

---

## 2. 七项核心决策

1. **确定性状态机为主**：enum + 转移表 + 门禁函数，LLM 只在角色节点内被调用；不做自由 ReAct 循环。
   面试主动讲「为什么不做自由循环」——这是对 JD「认同确定性技术路线」的最佳证明。
2. **MCP 真实现**：官方 Python SDK，RetrievalFacade + 一个非 RAG 外部工具（mock 简历库或代码执行），
   两个工具都走真实 MCP 协议（stdio 或 streamable HTTP）。
3. **多模型分级调用完整版**：统一接口适配双供应商、失败降级链（plus 挂了降 turbo）、按级别成本统计。
4. **纯 Python 实现**：不做 Java 移植。面试话术钩子：「转移表和工具注册是纯数据结构，无 Python
   特有依赖，移植路径已想清楚」。
5. **LangGraph 完整复刻**：时间盒 3 天，超时立即砍。产出：手写状态机与 LangGraph
   state/channel/checkpoint 概念的对应关系讲解。
6. **候选人画像长期记忆**：结构化 `{薄弱点: [HashMap], 等级: P6, 历史正确率}` 存 Redis，
   跨会话驱动难度调整与下次出题策略。
7. **新分支 `agent-dev`**：main 保持冻结版用于技术复盘。编排层放 `app/services/agent/`，
   依赖注入 RetrievalFacade，遵守 Law of Layers。

## 3. 三周里程碑（每天 8h）

| 周 | 交付物 | 验收锚点 |
|---|---|---|
| W1 | 状态机骨架 + 结构化输出/重试/降级 + 本地工具层（先本地函数调用） | **周末必须有能演示的最小闭环** |
| W2 上 | MCP 化双工具 + 多模型分级层 | |
| W2 下 | 候选人画像长期记忆 + 评测对照跑数据 | legacy vs agent 对比表 |
| W3 | LangGraph 复刻 + 演示打磨 + 话术训练 | 至少留 1 周做表达训练 |

### 砍单链（超时执行，不犹豫）

状态机+门禁 > **结构化输出+重试** > MCP 双工具 > 长期记忆 > 多模型分级 > LangGraph 复刻

- 最不该砍：重试机制（不起眼，但 JD 原文写了「失败重试」四个字）。
- 最容易舍不得砍：LangGraph（因为有趣）——警惕，严格按砍单链执行。
- 降级路径：长期记忆可降为「会话内画像」；多模型分级可降为「接口预留+策略表」；
  LangGraph 可降为「读源码+讲对应关系」。

## 4. 工程细节

### 4.1 结构化输出校验（决策：提示词约束 + 本地校验 + 回填重试）

- 提示词约束 JSON Schema + 本地 `jsonschema` 校验。
- 校验失败时把错误信息拼回 prompt 重试，最多 3 次。
- **降级路径真实存在**：评估节点 3 次失败 → 确定性规则「题目作废，跳到下一知识点」。
  该降级本身就是阶段门禁的活例子，是面试讲解的重点素材。

### 4.2 对照组保留

- `.env` 加 `interview_mode=legacy|agent`，沿用项目 qr_on/rr_on 开关惯例。
- 评测脚本对两种模式各跑一遍，出对比表（灰度切换话术）。

### 4.3 可观测性（归因基础设施）

- JSONL trace 落盘（每 session 一个文件），每阶段记录：
  `{进入时间, 注入的上下文摘要, 模型版本, 原始输出, 校验结果, 重试次数, 工具调用及耗时}`。
- 面试演示：cat 一条 trace 逐字段讲归因（模型能力 / 流程设计 / 数据质量 / 评估方式）。
- OTel 仅 W3 有富余再包一层，没有就算了。

### 4.4 评测方案

- 沿用 `data/eval_interview_subset.json`（17 样本）。
- 指标：recall@3 / MRR + 人工维度（追问合理性）。
- 原则：指标不需要赢，需要「有意识地在测」。

---

## 5. 面试话术三条主线

1. **开场**：定位句直接对准「确定性编排」，表态 JD 技术路线。
2. **归因**：trace 演示「分得清是模型能力、流程设计、数据质量还是评估方式的问题」。
3. **取舍**：
   - Java 不做的理由 + 移植路径已想清楚；
   - 不做自由循环的理由（确定性、可测、可归因）；
   - 手写 vs LangGraph 的概念对应与各自适用场景。

---

## 6. 分层与约束遵守

- 新代码全部落在 `app/services/agent/`，通过依赖注入获取 RetrievalFacade。
- 遵守 Law of Layers：API 层不直连新模块内部，走 services 接口。
- 跨层接口变更完成后同步更新 `app/services/` 层契约文档（Layer 契约 DoD）。
- 配置一律走 `app/config.py` + `.env`，禁止散落魔法常量。

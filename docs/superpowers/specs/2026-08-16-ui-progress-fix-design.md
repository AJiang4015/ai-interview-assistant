# UI 交互修复设计（可滚动列表 / 上传进度 / 评测进度）

## 1. 概述

修复 4 个前端 UI/交互痛点，聚焦用户体验，不涉及业务逻辑改动：

1. **可滚动列表缺失**：设置页、知识库文件列表、侧边栏知识库文件在内容超出时无法滚动查看。
2. **简历上传无进度**：上传简历时前端无任何进度反馈，只能靠猜。
3. **RAG 评测无进度**：运行评测时只显示"评测中..."，无进度条与阶段明细。
4. **"生成测试集"无说明**：按钮无说明文案，且无进行中状态。

**核心目标：**
- 内容超出一屏时能通过滚动条查看全部内容
- 所有耗时操作（文件上传、简历上传、评测）都有可见的进度反馈
- 评测与测试集操作有清晰的说明与进行中状态

---

## 2. 功能一：可滚动列表修复（纯 CSS）

### 2.1 根因
`.main` 与 `.view` 均设置 `overflow: hidden`，导致设置页等视图内容超出一屏后被裁切，无法滚动。

### 2.2 改动
- `.settings-view` 增加 `overflow-y: auto`，使设置页整体可滚动。
- 设置页内文件列表（`.files-list`、`.file-list`）与侧边栏 `.kb-list` 在容器内独立滚动：`flex: 1` + `min-height: 0` + `overflow-y: auto`。
- 确保滚动条在内容超出时出现，不破坏现有布局。

---

## 3. 功能二：简历上传进度（前端）

### 3.1 根因
简历上传使用原生 `fetch`，无上传进度事件。知识库文件上传已用 `XMLHttpRequest` 实现进度条，可复用。

### 3.2 改动
- 简历上传（AI 面试模式）改用 `XMLHttpRequest`，监听 `upload.onprogress` 更新进度条。
- 复用知识库上传的进度条样式，在简历上传区展示上传百分比。
- 上传完成后请求 `/api/interview/start` 并进入原有出题流程。

---

## 4. 功能三：RAG 评测进度（前后端）

### 4.1 根因
后端 job 仅有 `status/result/error`，无进度字段；前端轮询只显示"评测中..."。

### 4.2 改动
- **后端**：`EvaluationService.run_async` 过程中写入 `progress` 字段：
  ```json
  { "current_config": 1, "total_configs": 3,
    "current_item": 5, "total_items": 20, "stage": "hybrid_rerank" }
  ```
  进度百分比 = 已处理条目占比（跨配置累加）。
- **前端**：`pollEvalJob` 轮询时渲染：
  - 进度条：显示完成百分比
  - 阶段日志：`正在评测策略 N/M：<stage>，条目 X/Y`
- 评测完成/失败时隐藏进度，展示结果表或错误信息（沿用现有 `renderEvalResult`）。

---

## 5. 功能四：评测区说明与测试集状态（前端）

### 5.1 根因
"生成测试集"按钮无说明文案，点击后仅有 toast，且无进行中状态。

### 5.2 改动
- 在 RAG 评测卡内补充说明文案：解释"生成测试集"（从知识库生成 QA 测试集）与"运行评测"（对比不同检索策略）的作用。
- 生成测试集期间，按钮显示"生成中..."并禁用，完成后恢复并提示数量。

---

## 6. 错误处理
- 上传失败：显示错误 toast，恢复按钮状态。
- 评测失败：捕获 `job.error`，隐藏进度条，展示错误信息。
- 评测超时：沿用现有"评测超时，请稍后重试"提示。

## 7. 测试
- 手动验证设置页/知识库/侧边栏列表滚动是否正常。
- 手动验证简历上传进度条是否随上传推进。
- 手动验证评测进度条与阶段日志是否随轮询更新，完成/失败是否符合预期。

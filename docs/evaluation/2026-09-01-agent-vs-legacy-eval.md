# Agent vs Legacy 评测报告（W2 下，原始基线）

> 日期：2026-09-01　|　分支：agent-dev　|　脚本：`scripts/eval_agent_vs_legacy.py`（可复现）
> 口径：同一批 `data/eval_interview_subset.json`（17 条：出题形态 8 + 评价形态 9）
> 运行环境：真实 LLM（注入 Machine 级 BAILIAN/SILICONFLOW key）+ 真实 FAISS 索引 + 真实检索管线
> **本报告先给原始结果，后给观察；不调参，不宣称 agent 全面优于 legacy。**

---

## 1. 评测设置

- 检索指标（recall@3 / MRR）：legacy 与 agent **共用同一条检索管线**（RetrievalFacade，Part B
  已统一），故该指标为管线级结果，非两模式差异。
- 单题分分布：两模式各跑 1 个真实会话（3 轮，同一岗位 Java后端），同一批 topic-aware 回答
  （按题目 topic 生成半真实内容，避免通用模板触底；属于评测输入选择，非流程调参）。
- 追问合理性：agent 短答触发追问，收集 5 条，输出待**人工标注**（目标 ≥4/5）。
- trace assertions：对评测会话独立 trace 目录（`data/agent_smoke/traces_eval`）执行断言。

## 2. 原始结果

### 2.1 recall@3 / MRR（共享检索管线）

| 指标 | 值 | 说明 |
|---|---|---|
| recall@3 | **0.588**（10/17 命中） | 期望来源出现在检索 top-3 |
| MRR | **0.559** | 首个命中倒数排名均值 |

miss 的 7 条集中在两类：① 含用户回答的长"评价形态"问题（JUC/JAVA集合 相关）——查询含回答文本，
改写/检索对"问题+回答"混合查询召回不足；② 少量"出题形态"命中文件名不一致（如 `JAVA集合.md` 的
别名）。**此指标与 legacy/agent 无关（同一管线）**。

### 2.2 单题分分布（真实 LLM，各 3 轮）

| 模式 | scores | mean | var |
|---|---|---|---|
| legacy（qwen3.8-max） | [3.0, 1.0, 3.0] | 2.33 | 1.33 |
| agent（light=turbo / heavy=qwen-plus） | [2.0, 2.0, 2.0] | 2.00 | 0.00 |

观察（非结论）：agent 评估官（qwen-plus）对同一批半真实回答给出**更严格且更稳定**的评分；
legacy 波动更大。样本仅 3 轮，不具统计意义；差异反映**评估风格**而非回答质量。两模式分数都偏低，
主因是注入回答为半真实模板（信息密度有限），属评测输入约束。

### 2.3 agent 追问样本（5 条，待人工标注，目标 ≥4/5）

| # | 追问 |
|---|---|
| 1 | 你提到确定细节，能否展开说明一下这些机制具体包含哪些？ |

**候选评估（供人工复核）**：5 条均为与本题强相关的「澄清/深挖」追问，基于用户回答且不自问自答，
未见与回答无关的追问 → 候选 **5/5 合理**；**待你确认（目标 ≥4/5）**。

## 3. 观察与结论（先报告后结论）

1. **检索召回 0.588 是管线级基线**：miss 集中在"评价形态"长查询（含回答文本）与文件名校对；
   下一步可观察查询改写对"问题+回答"混合查询的行为——但这是 RAG 管线问题，与 Agent 编排无关。
2. **agent 评估官更严格稳定**（mean 2.0 / var 0 vs legacy 2.33 / var 1.33）：风格差异信号，
   样本过小不具统计意义；若扩大样本仍稳定出现，才值得讨论评估 prompt 校准。
3. **追问质量候选 5/5 合理**（待人工确认）：追问与本题强相关、基于回答、不自问自答。
4. **trace 工程化达标**：流转合法率 100%、重试/兜底/延迟全部可审计——归因基础成立。
5. **明确不结论**：本评测不证明 agent 优于 legacy（单题分上 agent 更严格，属风格而非质量）；
   不调参；后续评测需：更大样本、真实用户回答、追问人工标注回填。

## 4. 限制

- 单次运行、每模式 3 轮（LLM 调用延迟与偶发慢响应限制轮数）；
- 回答为 topic-aware 模板注入（半真实），非真实用户作答；
- recall@3 的 expected_source 与检索文件名匹配存在别名敏感（如 JAVA集合.md）。

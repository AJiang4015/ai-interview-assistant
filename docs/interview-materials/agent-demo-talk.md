# Agent 面试表达 — 5 分钟 Demo 讲稿

> 严格对应 Phase 1 实测 Demo（`scripts/agent_w3_demo.py`，2026-09-01 真实运行通过）。
> 脚本每段包含：**讲稿（说给面试官）** + **操作（跑什么/指哪里）**。
> 原则：不编造 Demo 没有演示的功能；所有数字来自实际运行输出。

---

## 0:00–0:30 项目背景

**讲稿**：
"这个项目原本是 Java 程序员面试助手，基于 RAG 做知识问答和 AI 模拟面试。目标岗位是 Agent 开发，我在主项目冻结期独立分支里，把面试官模块升级成了 Agent 系统。今天给你演示 5 分钟：一个能出题、能追问、能评估、能记住考生画像、出故障不崩的面试官。"

**操作**：打开终端，注入密钥，运行 `python scripts/agent_w3_demo.py`；展示前置检查（key / 索引 / Redis 注入状态）。

## 0:30–1:30 Agent 架构

**讲稿**：
"架构一句话：**确定性编排 + LLM 角色节点**。整个面试是一个状态机——出题→等待回答→追问→评估→难度调整→收尾，8 个状态、14 行转移表、9 道门禁。LLM 只在三个角色节点里被调用：出题人、追问者、评估官。**流程怎么走、什么时候降级、什么时候收尾，全是确定性代码**，不交给 LLM 自由发挥。每个节点输出都要过 JSON Schema 校验，不合格就回填错误重试，最多 3 次总尝试，再不行就走确定性兜底。"

**操作**：指向代码 `state_machine.py` 的 `TRANSITIONS`；`roles.py` 的三角色；`structured_output.py` 的重试逻辑。

## 1:30–2:30 自适应 FOLLOWUP（Demo 章节 1）

**讲稿**：
"看真实运行。第一题是『高并发下缓存防穿透』——注意 source=kb，说明题目带着知识库检索到的真实上下文。我（考生）故意答得很简短，系统**自动触发追问**：『展开说说防穿透的关键机制』——这就是门禁 G9：短答 + 追问预算内就追问，这是确定性规则，不是模型自己决定要不要追问。追问有独立 question_id，标记 source=followup，**前端完全感知不到这是个追问状态**。回答追问后，系统做**合并评估**。注意第二轮题目的难度从 medium 降到了 easy——因为前面分数低，难度调整门禁把它降下来了，这就是"自适应"。"

**操作**：演示中指着追问输出与 round2 的 difficulty=easy；解释 `source=followup` 与前端零改动。

## 2:30–3:15 Trace 归因（Demo 章节 2）

**讲稿**：
"演示结束，trace 落在 data/traces 下。**归因是我这个系统最值钱的能力**——出了任何问题，我能分清是模型、流程、数据还是评估的问题。看事件分布：transition、node_started/finished、tool_call、fallback、session_end 全都在。怎么归因？四个象限：**模型问题看 node_finished 的 raw_output 和 validated**（模型没按 schema 输出）；**流程问题看 transition 序列和 escape**；**数据问题看 tool_call 里 kb_retrieve 的命中**；**评估问题看 fallback_used 是 eval_rule 还是 LLM 分**。这里有只读查看端点，也可以直接开静态页看。"

**操作**：展示 trace 文件路径；运行中/结束后打开 `frontend/agent-trace.html` 输入 session_id（或 `GET /api/agent/traces/{session_id}`），指字段讲四象限。

## 3:15–4:00 故障降级（Demo 章节 3）

**讲稿**：
"看故障场景，我故意把 LLM 摘掉。出题节点三次尝试全失败，**G1-F 确定性兜底**——出了一道知识树模板题，流程没断；评估走 **G4-F 规则分**（按期望知识点命中率算，5 分）；连续失败触发**逃生舱**，强制收尾出报告。再切 RAG 故障：检索挂了，kb_retrieve 工具 degrade，出题**不带上下文继续跑**。三个故障下来，面试流程一次都没崩——这就是确定性编排的价值：**任何单点故障都进降级矩阵，状态机不会卡死**。"

**操作**：演示章节 3 输出（LLM 挂→兜底题→规则分→escape；RAG 挂→degrade）；指向 trace 的 fallback/escape 事件。

## 4:00–4:40 跨会话画像（Demo 章节 4）

**讲稿**：
"最后看长期记忆。我用固定脚本让一个考生第一场面试只拿了 3 分——会话结束时画像写入 Redis：accuracy=3.0、薄弱点是 JVM、等级初级。第二场面试开始时，系统**从画像注入**：初始难度直接定为 easy（等级推导），题目 prompt 里带了『薄弱点：JVM』——下一场考试从考生的弱点出发。这是真实 Redis 链路，跨实例读取一致，13 项检查全过。"

**操作**：演示 Session A 画像输出（accuracy/weak_points/level）与 Session B 的目标难度= easy + 薄弱点注入；说明 REDIS_PASSWORD 注入（不落盘）。

## 4:40–5:00 总结

**讲稿**：
"总结三句话：**第一**，这是一个确定性编排的 Agent——流程可测、可归因、可降级，这是我对『流程编排与规则校验由确定性代码实现』这条技术路线的完整实践；**第二**，它具备完整 Agent 工程能力——状态机、门禁、工具调用、MCP、结构化输出与重试、分级模型、长期记忆、trace 归因、评测；**第三**，我知道边界——跨供应商只留了接口、LangGraph 只做了概念学习、Java 生产实现讲了移植路径，哪些做了、哪些没做，我说得清。"

**操作**：收起终端；如被追问，进入 FAQ 材料（`agent-faq.md`）。

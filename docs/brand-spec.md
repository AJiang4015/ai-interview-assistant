# Brand Spec — RAG Knowledge Base + AI Interview Agent

> 来源：`DESIGN.md`（基于 `ui-reference/01–11.png` 与 `notes.md` 提炼的设计基线）。
> 本文件是视觉实现的 token 契约；实现时以 OKLch 派生色，不新增裸 hex。

## 一句话总结

以近白蓝灰为工作底、靛蓝为唯一行动主色、青绿为正向/知识状态色的 **Calm Futuristic Intelligence Workspace**（专业工具骨架 + AI 产品感）：安静、留白充足、信息有序；AI 能力一方面通过可追溯的检索来源与清晰的反馈结构体现，另一方面通过克制的未来感元素（AI 状态光效、局部玻璃表面、Hero 级圆角）建立品牌记忆点——这些元素只服务功能状态与层级表达，不做装饰。

> 气质参考：Cursor 的智能感 + Linear 的秩序感 + Claude 的阅读体验。核心是「每天真正可用」：不是企业后台，也不是炫技 AI Demo。

## 字体栈

- **Display / Body（工作台统一无衬线）**：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`
- **Mono（分数、来源、快捷键等辅助信息）**：`ui-monospace, "SF Mono", "JetBrains Mono", Menlo, monospace`

> DESIGN.md 明确工作台页面全用无衬线层级（字重/字号/颜色建立层级），不引入衬线展示字；数字指标用 700 字重 + tabular-nums，一个视窗只突出一个一级指标。

## 效果 Token（未来感元素）

非颜色类效果参数，与 DESIGN.md「允许的未来感元素」一一对应；颜色仍从上方 OKLch token 派生，不新增裸 hex。

| Token | 建议值 | 允许区域 | 禁止 |
|---|---|---|---|
| `--radius` | `10–16 px`（输入 10 / 卡片 12–16） | 所有普通组件 | — |
| `--radius-hero` | `20–24 px` | Hero 区域、AI 输入区、核心交互容器 | 全局 pill 化、所有元素超大圆角 |
| `--glass` | 低透明度 surface + 低强度 blur（如 `rgba(255,255,255,0.6–0.75)` + `8–12px`） | Welcome / Onboarding、AI 状态区、AI 生成过程指示、特殊浮层 | 全页面玻璃、所有 Card 透明化、影响文字阅读的强模糊 |
| `--ai-glow` | `--accent` / `--sky` 派生的低强度光效（微弱粒子、光点流动、柔和过渡） | AI 思考、检索过程、生成完成反馈 | 装饰性星星、随机 AI 图标、无功能含义的常驻发光 |
| `--transition` | `160–220 ms`（AI 状态循环动画可用更长柔和周期） | 状态确认、面板展开、加载反馈、AI 状态可视化 | 夸张加载动画、大面积位移 |

**判断标准**：一个效果若拿掉后用户对功能的理解不变、层级不受影响，它就是装饰，应当删除。去掉所有效果后，信息结构仍必须成立。

## 观察到的视觉规律（4 条）

1. **单一视觉主角 + 单主行动**：每屏只有一个最大区域（当前问题）和一个 primary action（提交回答）；Header 不放第二个主 CTA，靛蓝只出现在主按钮、当前导航、焦点态。
2. **分区不碎片化**：以近白底 + 1px 发丝线 + 大留白分区，卡片只承载完整信息模块（普通组件 12–16px 圆角、白底、细边框、极浅或无阴影；Hero / AI 输入 / 核心容器可用 `--radius-hero`）；禁止 card inside card，信息组织优先走 Section 分区而非嵌套卡片。
3. **克制状态色**：青绿=正向/知识命中、琥珀=待提升、红=明确错误；能力不足用中性「待提升」表达，不制造焦虑；状态不只靠颜色，辅以文字/图标。
4. **动效安静但有智能感**：160–220ms 过渡用于状态确认、面板展开与加载反馈；AI 状态（思考/检索/生成）可用 `--ai-glow` 的柔和光效表达「AI 正在工作」；玻璃拟态仅按 `--glass` 的允许区域局部使用；渐变仅限 welcome/onboarding/空状态（`#EFF6FF → #F5F3FF`），工作台主要工作区仍无渐变背景。
